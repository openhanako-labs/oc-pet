# 动作栅栏扩容 —— 让模型说对的话能播出来

> 作者：奥菲莉娅（Ophelia）
> 日期：2026-09-20
> 状态：**已落地**（含测试护栏更新）
> 关联：`docs/表达决策层-2026-09-20.md`（同日另一条线）· `tests/test_do_aliases.py`

---

## 0. 一句话结论

`logs/oc_pet.log` 里有 **257 条「未知动作」警告**——不是模型选错了，是**它说对了、栅栏接不住**。

prompt 给模型看 17 个选项，别名表实际支持 22 个，而快照里可播的有 **53 个**。三个数字互不相等，说明清单是手写的，和模型能力脱节了。

---

## 1. 证据链

### 1.1 模型真的用过、但播不出来的

`logs/oc_pet.log` 里 LLM 实际输出的 gesture：

| gesture | 次数 | 别名表 | prompt 里 | 结果 |
|---|---|---|---|---|
| `歪头` | 4 | ❌ | ❌ | `未知动作 '歪头'` |
| `wave` | 2 | ❌ | ❌ | `未知动作 'wave'` |

加上刷屏的 `walk`（194 次）、`extra`（63 次），合计 **257 条警告**。

### 1.2 对照实验（deepseek-chat，真实 prompt 结构，10 个对话语境）

| 候选清单 | 有效 gesture |
|---|---|
| **旧 17 项平铺** | **2/10** |
| 全 53 标签 | 10/10 |
| 分组 25 项 | 10/10 |

旧清单下被判「无效」的名字：

```
开心 / 微笑 / 困 / 摸头 / 害羞 / 疑惑 / 思考 / 挥手 / 温柔微笑
```

**这些语义全都对。**它们无效纯粹是因为不在清单里——这正是 `歪头`/`wave` 的成因。

**结论：不是模型不会选，是清单里没有它想用的词。**

### 1.3 还有一个隐藏断点

prompt 里给的是**中文标签**（`灿烂笑容`/`害羞脸红`/`瞪大眼睛`），但 `_trigger_gesture` 只认别名表（69 条）和预设名。实测 **53 个标签里有 33 个过完两层仍是中文**，落到 `play_anim` 就是「未知动作」。

也就是说：**prompt 承诺了 41 个候选，其中大部分播不出来。**

---

## 2. 改了什么

### 2.1 别名表：22 → 69 条

`avatar/live2d_renderer.py` 的 `_AI_DO_ALIASES`。

扩容原则：**把「语义正确但当时没收录」的口语词全部接上**。

- **日志实证**（必须收）：`歪头`→`head_tilt`、`wave`→`waving`、`walk`→`walk`
- **常见口语同义**：`高兴`/`愉快`/`温柔`/`温暖`/`关心`/`欣慰`/`兴奋`/`惊喜`/`好奇`/`无奈`/`无语`/`委屈`/`疲惫`/`傻笑`/`摆手`…
- **分组标题词**：`平静`（模型有概率直接把分组名当动作名用）

### 2.2 新增「标签兜底层」

`_trigger_gesture` 里加了 0.5 步：

```python
alias_hit = g in self._AI_DO_ALIASES
g = self._AI_DO_ALIASES.get(g, g)

if not alias_hit and g not in self._EMOTE_PRESETS:
    from core.capability_snapshot import LABEL_TO_PRESET
    g = LABEL_TO_PRESET.get(g, g)
```

**为什么要这层**：标签表（`core/capability_snapshot.PRESET_LABELS`，53 条）和别名表是两个集合。与其把 53 个标签手抄进别名表，不如查表归一——**单一来源，换模型自动跟着变**。

**为什么只在别名表未命中时走**：别名表是人工调的语义优先表（`挥手`→ motion `waving`，比标签的 `arm_wave` 预设更符合直觉）。标签层只是兜底，不能反过来盖掉它。

### 2.3 prompt 清单：17 项平铺 → 25 项分组

```
开心:灿烂笑容/咧嘴大笑/咯咯笑/兴奋/眼睛发亮/得意
害羞:害羞脸红/羞怯/偷瞄/嘟嘴
惊讶:惊讶吸气/瞪大眼睛/挑眉
思考:思考/抬头往上看/抿嘴
疑惑:疑惑歪头/歪头/侧目/耸肩
生气:生气瞪视/翻白眼/眯起眼睛
失落:失落垂眼/低头往下看/叹气
困:犯困/打哈欠/伸懒腰打哈欠
平静:温柔微笑/连续眨眼/点头/身体轻晃
```

分组让模型**先定位情绪、再选具体动作**，比平铺一堆名词好选。

## 4. 更新了哪些护栏（以及为什么）

`tests/test_do_aliases.py` 的三条旧断言编码了**已被数据推翻的假设**：

| 旧断言 | 旧依据 | 修正 | 新依据 |
|---|---|---|---|
| 别名 10~40 条 | 「太多就回到选择困难」 | 10~120 条 | 实测 17 项清单只 2/10；上限把「模型想用的同义词」挡在外面 |
| prompt ≤25 项 | 「远小于预设总数」 | ≤45 项（且 <53） | 分组 25 项跑到 10/10；限制选项数不是目的 |
| prompt <300 字符 | 「太长是 [do:] 未使用的原因」 | <420 字符 | 319 字符的 25 项清单 10/10；**决定性因素是语义分组，不是长度** |

**新增两条护栏**（守住新发现的不变量）：

- `test_log_proven_gestures_are_playable` —— 日志实证用过的 gesture 必须在表里
- `test_prompt_options_are_all_resolvable` —— **prompt 承诺的候选必须条条可播**（这正是踩过的坑）

`tests/test_bugfix6_item_c_action_intent.py` 一条用例改为用不在别名表里的名字，保持「未命中→透传」的原测试意图；另加一条验证 `wave` → `waving` 的归一。

## 5. 没做的事（明确划界）

- ❌ **没有启用 `expression_director`**（同日另一条线）——它的接线位置错了（挂在 `[emotion:]` 上，而它生产里永远是 `neutral`），且「VA → 情绪」的映射经对照实验不可行（详见 `docs/表达决策层-2026-09-20.md`）
- ❌ **没有修 `walk`/`extra` 刷屏的调用方**——`walk` 在 miku 上无对应 motion（正常），但 194 次重复尝试说明有个调用方在无条件重试。那是另一个问题，未动
- ❌ **没有动 `[feel:]` 的 VA 映射**——几何最近邻只有 3/9，但那是「兜底路径」，主力仍是 `[action:]`

## 6. `walk` / `extra` 刷屏：已查明并修复（2026-09-20 晚）

### 6.1 定性：事件驱动，不是循环

时间分布先排除猜测：

| | walk | extra |
|---|---|---|
| 次数 | 194 | 63 |
| 时间跨度 | 23:01:49 → 23:56:45 | 23:07:50 → 23:56:59 |
| 中位间隔 | 12s | 17s |
| 同秒并发 | 0 | 0 |
| 连续块 | 194（最大块长 1） | 63（最大块长 1） |

从不连续、从不并发、间隔稳定 → **定时器/状态机驱动**，不是循环重试。

排除项：`chase` / `追` / `光标` / `physics` 在日志里**零次**出现——不是追鼠标。

### 6.2 根因：`set_anim` 的 atlas 判断错了对象

`pet.py:set_anim` 原实现：

```python
if anim == 'walk':
    if 'running-right' in self._renderer._frames:
        anim = 'running-right' if self._facing_right else 'running-left'
self._set_anim_seq(anim)
```

`_frames` 是 **sprite/atlas 渲染器**的帧表（`{序列名: [QPixmap]}`）。
Live2D 渲染器**也有** `_frames`，但它是**空 dict**（`live2d_renderer.py:578`）
→ 判断恒为 False → `'walk'` 原样下传 → miku 无 walk motion → 每 12 秒一条警告。

**完整触发链**：

```
MotionStateMachine.tick(500ms)
  → walk_chance 命中（normal=0.3 / active=0.7）
    → _start_walk → physics.start_walk
      → cb.set_anim('walk')            ← pet.py:set_anim
        → 'running-right' in {} → False
          → _set_anim_seq('walk')
            → play_anim('walk') → 未知动作 → WARNING
```

频率对得上：行走 + 休息（`min_pause` 2000~`max_pause` 5000ms）后的实际节奏
正好落在中位 12 秒。

### 6.3 `extra` 的来源：硬编码白名单

`pet_mixins/bubble_mixin.py` 原实现：

```python
safe_anims = ['idle', 'walk', 'extra']
if anim_name not in safe_anims:
    anim_name = 'idle'
```

**`extra` 从来就不是任何模型的可播动画名。**白名单本意是「防越界」，
写死与模型无关的名字，自己成了噪音源。

### 6.4 修法

| 位置 | 修法 |
|---|---|
| `pet.py:set_anim` | 按**渲染器能力**判断，不猜帧名：sprite 有 `running-right` → 换名（原行为）；Live2D 无 walking 类 motion → 降级 `idle`（位移仍由 physics 驱动） |
| `bubble_mixin` | 新增 `_safe_anim_names()`：向渲染器要**实际可播的动画名**（sprite 读 `_frames` 键 / Live2D 读 `_motion_files`），拿不到则退回最小集 `{idle}` |

**为什么降级而不是报错**：「模型没有走路动画」是**正常情况**，不是错误。
真正该报错的是「模型有的动作播不出来」。

### 6.5 验证

四种情形全部通过（`tests/test_anim_name_hygiene.py`，10 条）：

| 情形 | 期望 | 结果 |
|---|---|---|
| Live2D 无 walk motion（miku） | 降级 `idle` | ✓ |
| Live2D 有 walk motion（lafei） | 保留 `walk` | ✓ |
| sprite/atlas | 按朝向 `running-right`/`left` | ✓ |
| 无渲染器 | 退回 `{idle}`，非空 | ✓ |

守卫：`'extra'` / `'walk'` 不得出现在可播白名单；源码里不得再有硬编码赋值。

## 7. 与另一条线的关系

同日两条线都指向同一个教训：**「模型说对了 / 代码送对了」和「能播出来」之间隔着一道栅栏，而栅栏常常是手写的。**

| | 动作栅栏（本文） | 表达决策层 |
|---|---|---|
| 症状 | 模型给的动作名播不出 | 决策器挂在死标签上 |
| 根因 | 清单手写、与模型能力脱节 | 接线选错信号源 |
| 修法 | 清单改为**向模型要** | 已搁置（VA 映射经对照不可行） |

**共同点：不要手写「模型能做什么」的清单，向模型问。**
