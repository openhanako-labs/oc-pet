> 作者：奥菲莉娅（Ophelia）

## 0. 一句话

**不碰 LLM 契约、不问本地引擎，直接对文本做向量近邻，得出情绪类别 + 强度 + 连续 VAD。**

---

## 1. 它治什么病

同一个问题，之前两条路都撞墙：

### 路 1：VA 坐标映射（已放弃）

主 LLM 输出 `[feel:valence,arousal]`，我们试图把 VA 翻成情绪词
（`perception_mixin._va_to_emotion`）。

**实测失败**：VA 二维承载不了情绪细粒度。正价区（v ≥ 0.15）全塌成 `happy`，
而日志里：

| VA | 原句 | 规则判定 | 实际语义 |
|---|---|---|---|
| (0.6, 0.3) | 深夜还守着直播呀，记得让眼睛歇一歇 | happy | **关心** |
| (0.3, −0.2) | 快零点了还在调网关，眼睛该歇了 | happy | **关心** |

同日另一条线的对照实验（几何最近邻 3/9）方法不同，但指向同一困难。

### 路 2：改 LLM 契约（已否决）

要求模型额外输出 `[emotion:xxx]`。

**两条历史数据压着**：

- 2026-09-10：四个标签要求「必须同时出现」→ 模型**选择全不写**，14 次回复 **0 次**带 `[emotion:]`
- `[do:]` 作为**可选**标签 → 实测 **0 次使用**

本地 1.5B 做的契约对照实验也证实：**可选标签一律被无视**（0/6）。
而主 LLM 的行为本地模型测不出来（`models.json` 里是运行时引用，拿不到真 key）。

### 路 3：embedding 直接分类（本层）

**不增加任何标签要求、不依赖任何模型配合。** 直接拿文本算向量近邻。

---

## 2. 两个视角（实测差异巨大）

| 视角 | 输入 | 用途 | 实测命中 |
|---|---|---|---|
| `user` | 用户消息原文 | 让桌宠知道用户此刻什么情绪 | **11/14 = 79%** |
| `pet` | 桌宠回复文本 | 驱动桌宠自己的表情 | **12/18 = 67%** |

两者**共用一套算法与语料**，差异只在 `extra_corpus`：

```
user 视角：SDK 原始语料（1400 条 / 14 类）
pet 视角：同上 + core/data/emotion_corpus_pet.json（补 66 条桌宠视角）
```

### 为什么 pet 视角要补语料

SDK 语料是**第一人称倾诉**（「我今天有点累」「我害怕一个人走夜路」），
而桌宠说的是**第二人称嘱咐**（「记得让眼睛歇一歇」）。

同一套语料、同一个模型，只换说话人视角：

```
不补语料：2/6 = 33%   ← 「记得让眼睛歇一歇」被判 tired（抓到"歇"的字面，丢了"关心"的意图）
补 66 条：12/18 = 67%
```

**分布错配是真实的，补语料是有效的。**

## 3. 算法

忠实移植 SDK 的 `EmbeddingMessageClassifier`：

```
文本 → embedding 向量
     ↓
精确命中？（规范化后与语料完全相同）→ 直接返回该条
     ↓ 否
top-K(5) 近邻 → 相似度 > 阈值(0.65) 才采纳
     ↓
相似度加权投票 → 得票最多的类别
     ↓
强度 = 同类近邻的加权平均
VAD  = 采纳近邻的加权平均（查 EMOTION_VAD_PRESETS）
置信 = 相似度余量×0.55 + 投票占比×0.45
```

**低相似度一律回退 neutral**（不硬塞一个类别）——与决策器同一原则：
宁可不动，不能乱动。

## 4. 接线（决策 C）

### 主干：替换那个恒为 neutral 的 `emotion`

主链路上 `emotion` 变量**恒为 "neutral"**（`[emotion:]` 标签只有兜底才补）。
而它有三个消费者：

- `set_emotion_expression_only(emotion)` — 面部表情层
- `_set_anim_seq(body_anim, emotion=emotion, ...)` — 身体动作过渡风格
- `_current_emotion` — 情绪驻留状态

分类结果**直接替换**这个空值，三个消费者立即受益。
**不依赖决策器是否启用**（决策器是另一层：从候选里挑具体预设）。

### 用户消息：只记状态，不改表情

`_send_message` → 后台分类 → 存 `_last_user_emotion`。

**为什么不直接改表情**：用户的情绪不该立刻改变桌宠的脸——
那会让桌宠显得没有自我。结果供行为层/主动搭话参考。

### 连续 VAD → 渲染器

分类器不只给情绪词，还给**连续 VAD**。渲染器正好需要连续 VA 坐标
（`_va_target` → 每帧指数平滑 → 参数）。所以新增了公开接口：

```python
renderer.set_va_target(valence, arousal, hold_sec=3.0) -> bool
```

三个渲染器都实现（基类默认返回 False，Live2D / VRM 重写）。

**为什么这是 VA 的正确来源**：不是把离散情绪名查表成坐标
（那是「二维承载不了细粒度」的老路），而是从文本直接分类出的连续值。

**顺序要求**：必须在 `_sync_renderer_master_emotion` **之前**写
—— 那个方法里有 `_va_hold_until` 保护，且它会用 `_EMOTION_VA` 表
覆盖 `_va_target`（表里只有 7 个情绪，会盖掉分类器的连续值）。
有测试钉住这个顺序。

### 线程安全（这次没踩同一个坑）

两个接入点都在主线程：

- `_send_message` 是 Qt 按钮/回车回调
- `_do_engine_reply` 经 `engine_reply_signal` 排到主线程

而分类要走网络（100-300ms，偶发超时）。所以：

```
_on_engine_reply（后台线程）→ 提交分类任务 → QThreadPool
                                        ↓
                              结果存 _pending_reply_emotion
                                        ↓
_do_engine_reply（主线程）→ 读取已备好的结果 → 替换 emotion
                        未备好 → 静默跳过（不阻塞、不等）
```

**教训来自本层的前车之鉴**：`expression_director.decide()` 同步阻塞跑在主线程，
引擎卡死时每次回复卡满 8 秒。同类错误不犯第二次。

## 5. 置信度阈值（扫描定标，不是拍的）

`min_confidence` 初始拍了 0.45，实测发现会误杀 pet 视角样本
（「你怎么又卡了」→ anger 置信 0.44 被拒，但答案是对的）。

用两个视角的独立测试集扫了一遍：

| 阈值 | pet 命中 | user 命中 |
|---:|---|---|
| 0.35 | 12/18 | 12/14 |
| **0.40** | **12/18** | **12/14** |
| 0.45（原值） | 11/18 | 12/14 |
| 0.60 | 10/18 | 12/14 |

**取 0.40**：与 0.35 同分但更保守；0.45 会误杀 pet 视角 1 条。

> 扫到 0.00 命中也不变 —— 说明本测试集里没有「低置信但错」的样本，
> 阈值保护的真实收益在这个小样本上看不出来。**不要因此取消阈值。**

---

## 6. 已知局限（不要过度信任）

1. **置信度不是校准概率**——是「相似度余量」与「投票占比」的加权。
   用来排序可以，当概率用不行（与 `expression_director` 同一原则）。
2. **类别边界重叠真实存在**——桌宠的「关心」与「亲昵」相似度只差 0.02 的情况出现过
   （「记得按时吃饭」→ affectionate 0.96 / concerned 0.96）。
3. **pet 视角 67% 置信度不高**——测试集 18 条，样本偏小。
4. **补语料是手工写的**——规模不够，需要持续积累。
5. **首次启动慢**——要嵌 1400+ 条语料（实测 1-3 分钟），走缓存后秒起。
6. **阈值定标样本小**——18/14 条上扫出来的，样本变大后应重扫。

## 9. 与既有层的关系

| 层 | 职责 | 状态 |
|---|---|---|
| `emotion_classifier`（本层） | 文本 → **情绪是什么** | ✅ 启用 |
| `expression_director` | 情绪 → **具体表情预设** | ⛔ 关闭（引擎端点需显存宽裕的机器） |
| VA 连续层（`live2d_renderer._va_target`） | VA 坐标 → 逐帧参数平滑 | ✅ 保留（分类器的 VAD 可喂进去） |
| `_va_to_emotion` 规则表 | VA → 情绪词（兜底） | ✅ 保留（分类不可用时回退） |
