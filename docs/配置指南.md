# oc-pet config.json 配置指南

> 本项目配置文件为 `config.json`（运行时实际生效）。`config.template.json` 是
> **规范模板**（干净、完整、可复制），改坏了配置可从模板恢复。
> JSON 不支持注释，本指南就是 config.json 各字段的"注释说明"。

## ⚠️ 历史坑（改 config.json 前必读）

1. **重复 key 覆盖**：JSON 允许重复 key，解析时**取最后一个**。历史上出现过
   两个 `plugin_tools` 块（一个 `true` 一个 `false`），`false` 在后面的把
   `true` 覆盖掉，导致插件工具静默关闭。
   **改之前先检查：**
   ```bash
   python -c "import json,collections;
   def d(o,p=''):
    r=[]
    if isinstance(o,dict):
     c=collections.Counter(o); r+=[f'{p}.{k}x{c[k]}' for k in c if c[k]>1]
     for k,v in o.items(): r+=d(v,f'{p}.{k}')
    elif isinstance(o,list):
     for i,v in enumerate(o): r+=d(v,f'{p}[{i}]')
    return r
   print(d(json.load(open('config.json',encoding='utf-8'))))"
   ```
   输出 `[]` 才是干净。

2. **Python 3 `\w` 匹配中文**：写路由/正则时用 `[a-zA-Z0-9_]`，不要用 `\w`。

3. **JSON 不能带注释**：`//`、`/* */` 都会让 `json.load` 崩溃。要加说明写在这份指南里。

## 各区块说明

### agents / character / scale / opacity / behavior / theme_mode / window
- `agents`: 多桌宠实例列表（`enabled` 控制是否随启动出现；`position` 是桌面坐标）。
- `character`: 当前默认角色（如 `miku`；官方示例模型可用 `sample_live2d`）。
- `scale`: 整体缩放；`opacity`: 不透明度 0~1。
- `behavior`: 行为模式（`normal` 等，对应 motion/behavior.py 的 BEHAVIOR_MODES）。
- `theme_mode`: `auto`/`light`/`dark`。
- `window`: 窗口位置与尺寸（x/y 为 -1 表示由系统放置）。

### break_reminder / work_reminder
- 休息提醒：`idle_minutes` 空闲多久提醒；`gradual` 渐进式提醒。
- 工作提醒：连续工作超 `after_minutes` 提醒；深夜（≥`late_night_hour` 或
  <`late_night_end_hour`）阈值 ×`late_night_multiplier` 降频；
  `cooldown_minutes` 提醒冷却；`snooze_minutes` 稍后提醒间隔。

### tts / sfx / asr
- `tts`: `enabled` 总开关；`provider`（edge 等）；`edge_voice` 音色；
  `voices` 角色音色映射；`voice_emotion_map` 情绪音色映射。
- `sfx`: 音效开关/音量。
- `asr`: 语音识别（`whisper_local` + faster_whisper，`model`=small/medium 等）。

### proactive（主动搭话）
- `enabled` 总开关；`cooldown_minutes` 基础冷却；`daily_limit` 每日主动搭话上限（20）。
- `llm_generation`: 主动搭话是否走 LLM 生成更自然文案（默认 true；失败自动回退模板池）。
- `fullscreen_suppress` / `fullscreen_threshold`: 全屏（游戏/视频）时不打扰。
- `rules`: 规则池（按 idle_min 倒序匹配 foreground 分类，weight 是触发概率）。
- **429 相关**：`llm_generation` 每次触发会打一次 LLM（source="proactive"）。
  若限流严重可先关 `llm_generation`（回退模板池，不调用 LLM）。

### window_interaction / mouse_interaction
- 窗口交互（拖拽等）与鼠标反应开关。

### memory（记忆）
- `budget_*`: 注入 LLM 的记忆预算；`hybrid_bm25`: BM25 混合检索；`score_patch`/`score_patch_gain`: RRF 后的**显著度加权**（事实按 importance×confidence、场景按出现频次；只放大不缩小、不改变入选集，`gain=0` 即恒等；默认关）。
- `embedding`: 语义向量（默认关；缺失自动降级纯 BM25）。
  - `provider`: `local`（本地 ONNX 模型，默认）| `api`（OpenAI 兼容 `/v1/embeddings`，免下载模型、免 onnxruntime 版本约束）。
  - `api`（provider=api 时生效）: `base_url`（不含 `/embeddings`，如 `https://api.siliconflow.cn/v1`）/ `api_key` / `model`（如 `BAAI/bge-m3`、`text-embedding-3-small`）/ `dim`（服务端原生维度，仅一致性校验；0=不校验）。
- `recall` / `associate`: 场景回忆/联想（proactive 说带记忆的话）。
- `facts`: 事实库（LLM 抽取，`dedup_threshold` 去重阈值）。
- `reflection`: 反思引擎（事件流 → LLM 摘要，`interval_hours` 周期）。
- **429 相关**：`reflection` 每天一次 LLM 摘要；`facts` 每次对话抽取。
  限流严重可关 `facts.enabled` / `reflection.enabled`。

### focus
- 专注模式（默认关）：开启后主动搭话频率下降、气泡轻微辉光。

### screen（屏幕感知）—— 429 重点
- `enabled`: 总开关（关掉后完全不截屏、不打视觉 API）。
- `interval`: 基准截屏间隔（秒）；`interval_min`/`interval_max` 随机浮动范围
  （默认 84~156s，即约每 2 分钟一次视觉分析）。
- `blur` / `blacklist`: 隐私保护（高斯模糊 / 敏感窗口黑名单）。
- `compress`: 截图缩放+压缩（省流量/省 token）。
- `phash_threshold`: **感知哈希近邻去重**（0=关，默认关；建议 3~6）。原来的变化
  检测是整帧 MD5——光标闪一下、时钟跳一秒就失效，照打一次视觉 API。本阈值用
  dHash + Hamming 距离挡掉「像素变了但画面没变」的帧。对比基准是**上次真正分析
  过**的那帧，所以缓慢渐变会累积触发、不会无限跳过。实测（30 帧逐帧都有动画）：
  MD5 省 0 帧（打 30 次），阈值 4 省 28 帧（打 2 次）。过大会漏掉局部小变化。
- `llm_enrich`: LLM 语义增强（场景标注）。**每成功截屏一次都会打一次**
  （source="screen_enrich"），加上视觉 API 本身 = 每周期 **2 次** LLM 请求。
- `llm_enrich_cooldown`: **429 限流缓解**（新增，默认 300 秒）。场景未变化时
  最多每 300s 补一次 enrich；场景变化立即补一次（保持灵敏）。
- **429 调优建议**（按优先级）：
  0. 开 `phash_threshold`（如 4）：不降频率，只挡「画面没变」的白烧 API；
  1. 把 `interval_min`/`interval_max` 调大（如 240~420s），直接降低视觉频率；
  2. 保持 `llm_enrich=true` + `llm_enrich_cooldown=300`（默认），减少重复 enrich；
  3. 限流仍严重：`llm_enrich=false`（纯规则分类，不再打 enrich）；
  4. 终极手段：`screen.enabled=false`（关闭屏幕感知）。

### anti_repeat（反重复）
- 语义指纹 + 时间窗去重：`bg_window`/`fg_window` 窗口大小、
  `drop_threshold` 重复丢弃阈值。一般不用动。

### presence（轻存在感）
- 不说话只做动作：`min_idle_minutes` 空闲多久可触发；
  `interval_minutes` 触发间隔。**不调 LLM**（纯动作），429 无关。

### plugin_tools（插件工具）
- `enabled`: 是否扫描并启用 Hanako/本地插件工具（默认**保持 true**，
  桌宠全链路插件调用依赖它）。
- 108 个工具在线后，播放类自然语言（"播首歌"）由 **LLM 自动选 play 工具**处理
  （见 core/capability_registry.py 设计决策）；本地静态能力只保留确定性控制
  （暂停/下一首/状态/清空）。

### 其他
- `state_http` / `external_trigger`: 本地 HTTP 口（默认关）。
- `celebrating`: 庆祝态（撒花动作 + 完工音）。
- `render_format`: `sprite` / `live2d`（miku 用 live2d）。
- `greeting`: 开场问候。

## 429 根因速览（2026-08-23 排查结论）

| 来源 | 频率 | 是否 LLM |
|---|---|---|
| 屏幕视觉分析（screen 定时截屏） | 每 84~156s | 是（视觉 API） |
| 屏幕语义增强 llm_enrich | 每次截屏一次（已加 300s 冷却） | 是（Hanako） |
| 屏幕主动评论（_check_screen_proactive） | 5~15min 冷却 × 20% 概率 | 是（对话回复） |
| 主动搭话 LLM 生成（proactive） | 冷却 10min，每日上限 20 | 是（Hanako） |
| 对话回复 | 用户驱动 | 是 |
| presence（轻存在感） | 空闲 5min 后每 8min | **否**（纯动作） |

**主要嫌疑**：`screen.llm_enrich` 让"每次截图 = 视觉 API + enrich LLM 两次请求"，
8 小时高频期可达约 400+ 次 Hanako 请求，极易打满限流。
**新增缓解（感知哈希）**：`phash_threshold` 挡掉「像素变了但画面没变」的帧——
不降频率，只砍白烧的 API（实测 30 帧逐帧有动画时可省约 90% 视觉调用）。
**本次缓解**：新增 `llm_enrich_cooldown`（默认 300s）+ 场景变化立即补，
enrich 请求量预计降到约 1/4~1/8；建议用户再按上面调优步骤放大截屏间隔。

## 接入 Hana 连接器（MCP）—— 让 agent 能「拉」桌宠状态

桌宠的 MCP 服务端是 **streamable-http**，端点固定为
`http://127.0.0.1:<port>/mcp`（由 `PetMCPServer.url()` 生成，默认 8979）。

### Hana 侧填什么（设置 → 连接器）

| 字段 | 值 |
|---|---|
| 类型 | 远程 |
| 远程 URL | `http://127.0.0.1:8979/mcp`（**末尾 `/mcp` 不能省**） |
| 传输 | 自动 |
| 鉴权 | 无 |
| 请求头 | 留空（框里那两行灰色字是 placeholder，不是真值） |

### 前置条件（最容易漏的一条）

**桌宠必须在运行**，且 `config.json` 里 `mcp_server.enabled = true`（默认
false）。服务端起在**桌宠进程内**，桌宠一关，端口就没人监听——连接器
「刷新工具」自然什么都刷不出来。

### 连接器页那两块容易搞混

Hana 把内容分成两栏，空态文案长得很像，含义完全不同：

- **工具**（`toolsTitle`）：空态是「还没有工具。启动连接器后刷新一次即可看到。」
  —— oc-pet 正常会给出 **9 个 `pet_*` 工具**（`pet_state` / `pet_say` /
  `pet_set_emotion` / `pet_play_anim` / `pet_expression` / `pet_celebrate` /
  `pet_reset_idle` / `pet_capabilities` / `pet_hana_catalog`）。
- **MCP 应用**（`appsTitle`）：空态是「这个连接器还没有提供 MCP 应用。」
  它指的是服务端提供的**交互式界面**（MCP Apps 扩展，在 Chalkboard 里
  打开的那种卡片）。oc-pet 是纯工具型 server，不提供 UI，**这一栏永远是
  空的，不是故障**。

### 体检（不依赖 Hana）

```
python tools/probe_mcp_endpoint.py
```

它会区分两种失败：

- **端口没人听** → 桌宠没跑（或没开 `mcp_server.enabled`）。
- **端口在听但握手失败** → 服务端/协议/端口占用问题。

健康时输出：`initialize` 200（`serverInfo: oc-pet <version>`）→ 9 个工具 →
`pet_state` 带 `screen.last_description`（缓存的屏幕观察，**拉取路径**的数据端；
只读缓存，不会触发新截图）。

### 安全边界

只绑 `127.0.0.1`，且 **未实现 token 校验**（`auth_token` 曾写在文档里但代码
从未读取，已删）。本机任意进程都能调写工具（`pet_say` 等）；要真鉴权需另行实现。

## 陪玩游戏识别（`game`）

陪玩方向 P0-1：识别当前在玩哪款游戏、玩多久、中途离开过没有。
**默认开**，但它不做任何用户可见动作（不弹气泡、不说话），
只把事实发到 `EventBus` 的 `game_session` 事件上（说什么是 P0-3/P0-4 的事）。

```json
"game": {
  "enabled": true,
  "disabled": [],
  "games": []
}
```

| 键 | 含义 |
|---|---|
| `enabled` | 总开关，默认 `true`。关掉后零开销。 |
| `disabled` | 要剔除的内置条目 id 列表（如 `["lol"]`）。 |
| `games` | 自定义/覆盖条目，**留空即可**（内置 8 款开箱即用）。 |

**内置 8 款**（覆盖 PRD §1.2 的三类 P0 场景）：

| id | 名称 | 类型 |
|---|---|---|
| `wuthering_waves` | 鸣潮 | 二次元大世界 |
| `genshin` | 原神 | 二次元大世界 |
| `star_rail` | 崩坏：星穹铁道 | 二次元大世界 |
| `lol` | 英雄联盟 | MOBA |
| `dota2` | DOTA 2 | MOBA |
| `minecraft` | 我的世界 | Steam 单机 |
| `terraria` | 泰拉瑞亚 | Steam 单机 |
| `onimusha` | 鬼武者 | Steam 单机 |

### 加自己的游戏（不用改代码）

```json
"game": {
  "games": [
    {
      "id": "my_game",
      "name": "我的冷门游戏",
      "type": "steam_single",
      "process": ["mygame*.exe"],
      "title":   ["冷门游戏"]
    }
  ]
}
```

- 同 `id` → **覆盖**内置项（只改想改的字段？不行，覆盖是整条替换，建议把字段写全）；
  新 `id` → 追加。
- `process` / `title` 都可写字符串或数组；支持 `*` 通配 **也支持纯子串**，大小写不敏感。
- **匹配优先级**：先全表比进程名（更硬），再全表比窗口标题。所以
  `Client-Win64-Shipping.exe` 这种 UE 通用进程名要配标题才准。

### 认不出来的游戏也不会丢

前台分类是 `gaming` 但没命中白名单 → 退化成通用条目（名字取窗口标题）。
局限：这类条目没有进程模式、无法探测是否还在跑，约定**离开前台即结束会话**。

### 事件与边界

- 事件名 `game_session`，四态：`game_started` / `game_background` /
  `game_foreground` / `game_exited`。载荷 `payload=<事件 dict>`
  （⚠️ 不能叫 `event=`，会跟 `EventBus.emit` 的位置参数撞名）。
- **切走不算退出**：用户 alt-tab 查攻略，会话继续（只有进程真没了才报退出）。
- **探不到就保守续命**：窗口探测整体失败/权限不足时**不报退出**，
  宁可会话多留，也不触发一句不该说的话。
- **红线**（PRD §5.1）：只读进程名与窗口标题，**不读内存、不注入进程、不做任何自动操作**。

### 验证

```
python tools/verify_game_watch.py
```

只读，不弹窗、不碰桌宠进程。会真实枚举当前可见窗口、拿真实存在的进程
当“游戏”跑一遍会话流转，并打印总线收到的事件序列。

## 后台 LLM 全局闸门（`llm_gate`）—— 429 治理的最后半边

2026-08 那次 429 的成因不是“某个函数写错了”，而是**三条线程互不知情**：
屏幕视觉、语义增强、主动对话各自独立地往同一个 provider 打。

之前已各自为政地做了防护（屏幕遇 429 自己退避、adapter 自己重试、内部来源改走
`utility_model`、enrich 300s 冷却、截图 dHash 去重）——都是**单点防护**。
本闸门是那张**全局的网**。

```json
"llm_gate": {
  "enabled": true,
  "max_concurrent": 1,
  "cooldown_seconds": 60,
  "max_cooldown_seconds": 900,
  "budgets": { "vision": 120, "enrich": 40, "proactive": 30 }
}
```

| 键 | 含义 |
|---|---|
| `enabled` | 总开关（默认 true）。关掉 = 完全不管。 |
| `max_concurrent` | 同时放行的后台调用数（默认 **1**）。后台任务晚两秒无所谓，一起撞上去才是问题。 |
| `cooldown_seconds` | 撞一次 429 后全体静默的秒数（默认 60）。 |
| `max_cooldown_seconds` | 连续撞墙时冷却翻倍的**封顶**（默认 900）。60→120→240→…→900。 |
| `budgets` | **每源每小时调用总量**上限。`0` = 该源彻底不放行（当开关用）；不写的源不限量。 |

**冷却管频率，预算管总量。** 冷却应对突发撞墙，预算应对“长时段跑下来总量失控”——
两者缺一不可。

### 被拦住时会发生什么

- **抢不到并发槽**：放弃这一次，**不排队**（后台少做一次语义增强，
  比把线程堆起来健康）。日志里会看到“被全局闸门跳过（busy）”。
- **冷却中**：屏幕感知本轮直接跳过，等下个周期；语义增强同样跳过，
  **保留规则分类结果，不丢场景**。
- **超预算**：同上。日志会写“累计 N 次”。

### 调优建议

- 白天总觉得屏幕描述不够详细？先看日志里是不是频繁出现“被全局闸门跳过”。
  是的话把 `budgets.enrich` 调大，而不是把冷却调小。
- 想彻底安静：把 `budgets` 里对应源改成 `0`（比关整个 `screen.enabled` 精细）。
- 确认再也用不上：`enabled: false`。

### 自查

状态快照：`from core.llm_gate import get_gate; get_gate().stats()` →
当前并发上限、冷却剩余、429 次数、每源最近一小时的用量。

## 口型：起音 / 收音 与开口上限（`lip_sync`）

```json
"lip_sync": {
  "mouth_peak": 1.0
}
```

### 起了什么变化

口型时间轴给的是**阶梯**——每个字保持一个恒定开口度 0.345 秒，字与字之间
**一帧跳变**（写入时 weight=1.0，SDK 不插值）。而振幅那条路径**本来就有**
非对称包络（起快落慢）——**音素这条路没有**。

现在给音素路径补上了：**40ms 起音 / 90ms 收音**（收比起慢），与帧率无关
（换显示器不会变形）。这是对齐 AgentAtelierR 的参数。

### `mouth_peak`：开口度上限

**默认 1.0 = 不压**（与你现在的观感一致）。

为什么不当默认开：AgentAtelierR 用 55% 避免“每次都张满嘴”，
但 oc-pet 的 `/a/` 是**自己调到 0.95 的**（miku 模型实测值）——
压到多少是**看脸决定**的事，代码不该替你做这个审美决定。

想试就改这个数（改完重启桌宠）：

| 值 | 效果 |
|---|---|
| `1.0` | 不压（默认） |
| `0.75` | 只削最夸张的几种大开口 |
| `0.55` | AgentAtelierR 的档位，整体偏内敛 |
