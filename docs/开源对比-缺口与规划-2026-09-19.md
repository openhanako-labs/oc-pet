# oc-pet × 开源桌宠/Agent 框架 对比与规划

> 作者：奥菲莉娅（Ophelia）
> 日期：2026-09-19
> 来源：oc-pet 源码（ARCHITECTURE.md + 实测 memory_hybrid/memory_embedding）+ 开源分析资料（02-桌宠VTuber、07-Cortico×AgentAtelierR、AAAAGENT/Amadeus/AmadesuEngine README 原文）
> 定位：横向比对「我们缺什么 / 能优化什么 / 该新增什么」

## 0. 一句话结论

oc-pet 在**表达层、感知层、生命周期层**已经比绝大多数开源桌宠成熟（渲染/口型/TTS/ASR/屏幕感知/多宠/主动对话/MCP 提供端全齐）。它的本质是 **Hana 的翻译层（嘴+眼+表演者），不是脑**——LLM 推理、工具选择、多轮上下文、长期记忆主存储全在 Hana 服务端。

所以对比的「缺口」不是「功能缺」，而是**三个结构性断层**：
1. **脑在别处**：独立 Agent 循环 / 多模态视觉进对话 / subagent / 具身 全部未落地。
2. **渲染只到 2D**：VRM/3D 是占位，物理反馈为零。
3. **生态本地化浅**：本地 plugins/ 只有 1 个，MCP 提供端默认关，per-agent vision 未配导致 429。

而开源项目的真正参考价值，集中在三点：**表演标签协议（AgentAtelierR）、事件流批处理（Cortico）、Host 三分架构的权限持久化（Amadeus）**——其余要么是重复造轮，要么是 PPT 级。

## 2. 缺口清单（GAP — 结构性断层）

### G1 🔴 VRM / 3D 渲染（占位）
- `avatar/vrm_renderer.py` 全文件 `load()` 返回 False；`factory.py` 三处「未来 3D 扩展钩子」。
- 开源对照：AmadesuEngine（Unity VRM 真实渲染）、Mate-Engine（VRM 3D）。
- 决策：自研 3D 成本高、ROI 低（分类总览已否决 Blender 路线）。**建议：短期不碰真实 3D，只补 VRM 加载器骨架 + 物理反馈占位接口**，等明确需求再投入。

### G2 🔴 A2A / subagent 调用（红差距）
- `docs/playmate-gap-analysis.md` 标红：无通用 Agent 调用（Hermes/OpenClaw 类）。
- 开源对照：Amadeus（Work Provider 委派执行）、AAAAGENT（任务卡转交 Codex）。
- 决策：**这是「桌宠自主干活」野心的核心**。可借 Amadeus 的「角色叙述 / Provider 执行 / Host 权限」三分，让桌宠把活委派给 Hana agents（已有 7 个），而非自研 agent 运行时。

### G3 🔴 具身（Embody）未集成
- 只有 `emotion→参数` 抽象，无「语音/字幕/口型/表情沿同一条播放时间线」。
- 开源对照：Amadeus Embody 层（同帧时间线）。
- 决策：oc-pet 已有 lip_sync + [feel:]/[do:] 时间轴，缺的是**一个统一的表演时间线调度器**把口型/表情/动作绑到 TTS 播放进度。可借鉴 AgentAtelierR 的表演队列（去重/限长/冷却）。

### G4 🟡 记忆只到 BM25+向量融合，缺图关系 + 分层 + 检索加权（源码级证据：深度分析/01-ocpet-memory-vs-faustbot.md）
- **实测架构**：`memory_facts`(JSON) + `memory_reflection`(JSON) + `memory_hybrid`(BM25+cosine+RRF 纯算法模块) + `memory_embedding`(本地 ONNX) + `memory_filter`(隐私过滤)。**无图、无持久化向量索引、无检索加权**。
- `memory_hybrid.py`：cosine 路径受 `memory.embedding.enabled` 门控，默认 false → **多数用户跑 BM25-only**（确认初版判断）。
- 开源对照：FaustBot（SQLite nodes/edges + networkx + 双 NanoVectorDB + BM25 + rerank + 图）、Cortico（memoTiers/subconscious）。
- **值得借（P0）**：① `score_patch`（FaustBot 的 `[-0.15,0.15]` 单节点检索加权；oc-pet 当前 `memory_filter` 只有二值判断「是否进调度」，无法表达手动加权/降权）；② **持久化向量索引**（FaustBot 的 `chunks.vdb` 思路——当前每次 `recall` 都对 pool 重算 embedding，延迟随规模线性增长）；③ BM25 索引懒加载 + dirty 标记（P1）。
- **明确不引入**（深度分析01 判据）：SQLite 真源（JSON 在 `FACT_MAX_FACTS=2000` 规模够用）、networkx 图（记忆模型是「平铺+时间+证据强度」非图）、`_CrossLoopLock`（oc-pet 是 threading 架构、无 asyncio，不适用）、外部 rerank API（隐私+延迟冲突）、实体-关系抽取（短期无需求）。
- **oc-pet 已有强项（对比 FaustBot 不弱）**：零向量库依赖、fallback gate 贯穿全层、繁简折叠对称、CJK 2/3-gram、证据双时钟衰减（reinforcement 30天 / disputation 14天 + sigmoid confidence，比 FaustBot 静态 score_patch 更细）、隐私过滤（情感类不进调度避免恐怖谷）。AAAAGENT 召回公式 `P=C×(0.55+0.25A+0.15I+0.05E)` 可作 score_patch 情绪权重参考。

### G5 🟡 多模态视觉不进对话 + 屏幕感知占 73% LLM 时间（源码级证据：深度分析/04-屏幕感知与WS缺口.md）
- **73% 时间三根源**（同一架构债的三种症状）：① 一次屏幕变化 = 两次 LLM 调用（vision API `screen.py:660-680` + enrich LLM `screen.py:379-410`）；② 三消费者并发共用同一 provider（vision + enrich + proactive，无全局并发信号量）；③ MD5 整帧缓存颗粒太粗（光标/进度条/时间戳任一变化即换 hash，无相似帧检测）。
- 429 限流：harness_adapter 只处理 Timeout/ConnectionError，429 走 HTTPError 直接返回兜底、无退避；视觉 API 与对话共用 `models.chat`（vision 未配时 fallback）。
- WS 无 context 通道：`hanako_ws_client.send_prompt` 白名单只有 `text/displayMessage/uiContext/sessionFileRefs`，`extra_context` 被迫拼进 text → 污染会话标题/历史（`harness_adapter.py:809`）。
- 开源对照：Amadeus visual-context 链（图像仍随主 Chat，未独立 vision 路由）——**同源痛点，均未独立 vision 路由**。
- 决策：已支持 `models.vision`（2026-09-17 新增）+ `_UTILITY_SOURCES` 走 utility_model（已做的分离）；缺口在「用户未配置」+「无全局 LlmRouter 并发控制」+「无 pHash 相似帧检测」。

### G6 ✅（已更正，非缺口）表演标签已有白名单约束
- **2026-09-19 代码核实更正**：原判「模型自由猜动作名」不成立——`_AI_DO_ALIASES`（语义标签→预设/motion）+ `_AI_DO_PROMPT`（注入 prompt 白名单）+ `_build_action_prompt()`（「只能从这些里选」）+ 未命中 `return False` 安全回退 **均已存在**。
- 残余（低 ROI）：白名单是**静态**的（不随角色实际 motion/表情生成）；且 `[do:]` 全历史 0 次使用。
- 决策：**降级**。如做，只需把 `available_actions`（pet.json，动态）接进 `_build_action_prompt`。

### G7 🟡 本地插件生态浅
- `plugins/` 仅 1 个（linjian-peek 8 工具）；外部插件在 `~/.hanako/plugins/`。
- 开源对照：Amadeus Provider 生态、netease-music-mcp（18 工具）。
- 决策：把 Hana 侧已有 92 skills / 26 plugins 的目录，更主动地暴露成桌宠本地可调用的能力（当前只入目录不主动调）。

## 4. 新增清单（ADD — 开源有、我们无，且值得做）

### A1 🟢 Web 管理界面（角色/Prompt/记忆/召回可视化）
- 开源对照：AAAAGENT 网页管理（查看修改角色 Prompt、记忆、召回记录、上下文、语音、表现预设、连接状态）。
- 价值：oc-pet 当前只有托盘/右键/面板，调试记忆召回不直观。
- 成本：中（复用现有 `status_http_server` 8977 + 一个轻前端）。

### A2 🟢 能力目录快照（动作/表情白名单约束）
- 开源对照：AgentAtelierR `motionGroups` 快照 + face 9 类 + action 12 类。
- 价值：堵 `[do:]` 模型猜动作名的幻觉风险；统一表情/动作语义。
- 成本：低（加一张白名单表 + 快照生成）。

### A3 🟢 表演时间线调度器（Embody 轻量版）
- 开源对照：Amadeus Embody 同帧时间线。
- 价值：把口型/表情/动作绑到 TTS 播放进度，提升「在场感」。
- 成本：中（在 `conversation_engine` 的 on_reply 阶段加一层调度）。

### A4 🟢 A2A 委派骨架（借 Hana agents）
- 开源对照：Amadeus Work Provider 委派、AAAAGENT 任务卡转交。
- 价值：让桌宠「把活派出去」，是自主 agent 野心的落点。
- 成本：高（需定义委托协议 + 权限边界 + 结果回灌），建议作为 v2 主线。

### A5 🟢 Host 权限/恢复持久化层（轻量）
- 开源对照：Amadeus Host 三分（角色/Provider/Host）。
- 价值：重启恢复关键状态（当前靠 Hana 会话 ticket）。
- 成本：低-中（抽一层 `host_state` 持久化 identity/permission/artifact）。

### A6 🟢 微信/跨端延续对话（可选）
- 开源对照：AAAAGENT 微信延续对话。
- 价值：脱离桌面也能接话。
- 成本：中（需微信桥，合规风险待评）。

## 5. 不建议做的（PPT 级 / 重复造轮 / 边界外）

- ❌ 自研完整 3D 渲染引擎（ROI 低，AmadesuEngine 已用 Unity 路线）；
- ❌ 抄 FaustBot 的 GraphStore 存储子系统（重，只抄检索不抄存储必炸）；
- ❌ 直接引用 AgentAtelierR 的 Dart 代码（无 license，仅可参考设计）；
- ❌ 深度集成 Cortico（5 天新仓 v0.1.1 pre-release，接口未稳，等 v0.2）；
- ❌ 把 Amadeus 部署为 Android 应用（桌面场景不同栈）；
- ❌ 自研独立 LLM 推理循环（oc-pet 的 Hana 翻译层选型正确，direct 模式仅兜底）。

## 7. 关键判断（写进日记的锚点）

1. **oc-pet 不是「功能缺」，是「脑在 Hana、手在本地」的分工选型**——对比开源独立 Agent 桌宠时，不能用「它有没有 LLM 循环」判优劣，要看翻译层做得扎不扎实。结论：扎实。
2. **记忆缺口的精确表述**：不是「记忆弱」，是「只到 BM25+向量融合，缺图关系层 + 分层记忆」。开 embedding 默认即可补一半。
3. **开源真正可抄的三件事**：表演标签协议（AgentAtelierR）、事件流批处理（Cortico）、Host 权限持久化（Amadeus）。其余要么重复造轮，要么 PPT 级。
4. **A2A 委派是「桌宠自主赚钱/干活」野心的结构性落点**——但应借 Hana 已有 7 个 agents 做委派，不自研 agent 运行时。

## 8. 证据链与覆盖清单（定稿附）
